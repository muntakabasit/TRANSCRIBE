## 1. Correction: optional instrument, not a new learning interface

The strongest Ofa Rick original GitHub record directly available says the human **does not want compulsory typing, dragging, repeated questioning, quizzing, or a predictable lesson protocol**. Ofa Rick should **come to the work**, support a natural conversation or creative action, show a comparison or instrument only when useful, and withdraw. A learning instrument's success cannot be equated with completing the instrument. Jara records **assisted success ≠ understanding ≠ transfer**.

Therefore the human-carried proposed “Learning Instrument Forge” is useful as a **capability question, not a subsystem decision**, and its sliders/controls are a *possible invited experience*, not a required pathway.

DAWT Design's lawful task is **make a specific visual relationship perceptible and examinable**. Ofa Rick's lawful task is **decide, within its own source-authorised responsibility, whether and how a learner could use that relationship beyond the initial encounter**. Transcribe's lawful task is source custody and source-preserving presentation. We must not turn DAWT Design into Ofa Rick's learning adjudicator or Transcribe into a tutor.

### A — DAWT DESIGN / TRANSCRIBE MEDIA ENCOUNTER

**Purpose:** render the spatial mechanism exciting, vivid and worth examining again, *without claiming skill acquisition*.

One 20–30-second (proposal only) visual essay:
- 00–04: original text anchor and editorial question: **“Why does one thing command attention?”**.
- 04–12: split-type spatial composition unfolds; words separate, illustrative image holds the gap.
- 12–22: same factual content re-composed as centred-object and photo-frame relationships, with visibly different attention paths; reject circle crop if genuine source image subject is unavailable/unsafe.
- 22–30: quiet A/B comparison and chance to **return to exact original / listen to commentary if actually generated and labelled / keep / leave**.

Motion must cease when the person wants to inspect it. Words never pretend to be the original source author's exact typography. Synthetic voice, if later produced, says **GENERATED COMMENTARY**, not `ORIGINAL SPEAKER`.

**Visual success is NOT proof of learning.** Qualitative evidence: subject recognisability, genuine mechanism clarity, human-valued juxtaposition, accurate source attribution, no filler, screen-reader transcript, response/exit freedom, rendering performance.

### B — OFA RICK / OPTIONAL SITUATED INSTRUMENT

**Purpose:** help a person notice a compositional relationship *while actively thinking about a real piece of work*, and only if an instrument would help more than discussion or the source alone.

**Entry:** The person's actual design task stays present, e.g. a poster where a single key message is being lost. A spoken remark such as “I can't tell what I'm meant to notice first” can justify a comparative overlay or a quick live demonstration. **No mandatory change of mode**.

**Example live instrument (proposed):** a small editable composition, with **headline scale** and **visual separation** controls; optionally a contrast toggle and side-by-side before/after. Controls may be touched, described aloud or controlled by accessible keyboard; the person may simply watch the comparison, talk, ignore it or dismiss it. **The real task remains primary.**

**Withdrawal test:** Rick closes the instrument when no longer needed. Later in a materially different composition—say a film title over moving people rather than a static product poster—the person may independently choose or reject a layout relation. A voluntary observed design move is more compelling evidence than filling a quiz. One move still does not prove enduring capability; selection, understanding, transfer and independent repeatability must be distinguished by the Ofa Rick owner.

**Context-specific negative example:** `frame over photo` may make words stand out in a static campaign but obscure faces, subtitled speech or a final community gathering in Damba. A competent designer must know when **not** to apply it. Don't change actual Damba source or treat it as an authorised learning fixture.

## 4. Component contract before any engine

Do **not** create a Learning Instrument Forge service now. Later, if a real dual encounter demonstrates the need, negotiate only a bounded, recipient-requested specification:

```text
source_set: immutable original source IDs + permission scopes
referent: the real question / human material, source-grounded
representation: vector/media study with visible interpretive labels
allowed_moves: inspect / compare / alter / speak / dismiss
state: draft / viewed / instrument_requested / returned / withdrawn
human_control: can skip / turn off / correct / leave
evidence: independent observed action, if present, not inferred mastery
source_return: original locator + commentary/projection provenance
rights: no publication or project routing merely through study
```

This would be *a transportable content/interaction specification*, not shared ownership, not a universal component renderer and not execution permission.

## 5. One lightweight first encounter — conditions and stop

1. **Stage A:** display S01 original plus one manually authored, source-truthful visual comparison; do not require generator/model usage or three additional sources.
2. **Human / Studio design observation:** Did A make anything newly visible, and could the original be recovered?
3. **OFA RICK recipient decision (not DAWT Design):** Is there an authentic ongoing creative question where an optional instrument is actually helpful? If not: **NO INSTRUMENT**, which is a valid outcome.
4. **Stage B (only if justified):** same source grammar, overlay/manipulable relation within the person's real work. No compulsory exercises, no forced tutor mode.
5. **Withdrawal/transfer pressure:** inspect later independent application in genuinely different work without substituting this for a graded test. Record UNKNOWN where there is no later evidence.
6. **Stop and return:** no app build, provider login, bulk ingestion, Damba edit, voice generation, autonomous learner profile or repository branch promotion from this contribution.

**Potential important result:** A might reveal meaning without teaching anything. B might help the moment but be unnecessary later. Both could fail. The useful question is **which representation fits which human purpose**, not whether one shared engine automatically makes both.
